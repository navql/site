What NavQL does with PostgreSQL

Built for the way you work with PostgreSQL.

Everything below works on PostgreSQL today.

Edit rows, then commit once

Change cells, insert, duplicate and delete rows in the grid. Every change stays pending (yellow, green, red) until you press ⌘S; Preview shows the SQL first and the whole batch commits in one transaction.

Related rows, as a tree

Open a row and see everything linked to it by foreign keys: the rows it points to and, for each table that points back, how many rows and the first ones. Each row opens its own relationships, as many levels deep as you like.

Activity: sessions, top queries, health

Every session on the PostgreSQL server with its query, state and wait, including who blocks whom. Cancel a query or end a session (pg_cancel_backend, pg_terminate_backend). Top queries come from pg_stat_statements.

Backups with pg_dump

Back up a whole database in one click with pg_dump --format=custom. It runs in the background, streams straight to a file, works through the SSH tunnel and shows progress. Restore with pg_restore.

Visual query builder

Pick a table, add the tables linked to it by foreign keys (or join any table with your own ON), filters, aggregates, HAVING and calculated columns. The SQL is written live, and you can save the builder or open the SQL in an editor tab.

Read only that really is

Mark a connection Read only and NavQL accepts only reading statements, then runs them inside a READ ONLY transaction on PostgreSQL, so a CTE with DELETE or a function that writes is refused too.

Also included

The details that save time.

  • Sidebar with tables, views, materialized views, functions and procedures, by schema; switch databases with ⌘K
  • Errors show the DETAIL and HINT PostgreSQL sends back
  • Truncate cascade lists every table that references the one you empty, then runs TRUNCATE … CASCADE
  • Health points out unused and duplicate indexes, invalid indexes, dead rows, stale statistics and XID wraparound risk, each with the command that fixes it (DROP INDEX, VACUUM…), which never runs on its own
  • Settings lists pg_settings with defaults and the source of each value; Review with AI suggests changes as ALTER SYSTEM commands
  • Cancel a running query from the editor; reset pg_stat_statements from the Activity tab
  • Filters on any column (=, contains, IN, BETWEEN, IS NULL…) or a free WHERE
  • Database diagram from the foreign keys, exported as PNG or SVG

Questions

Good to know.

Is NavQL a free alternative to pgAdmin?

Yes. NavQL is free for personal and commercial work. Unlike pgAdmin it also opens MySQL, SQL Server, MongoDB, Redis and SQLite in the same app. pgAdmin is PostgreSQL only and has more server administration screens, such as roles and restore.

Which PostgreSQL versions does NavQL work with?

NavQL talks to PostgreSQL with the standard pg driver, so current releases work. For backups the app uses the newest pg_dump it finds on your computer, which must be the same version as the server or newer.

Does NavQL work with Supabase, Neon, TimescaleDB and CockroachDB?

Yes. They speak the PostgreSQL protocol and appear in the connection form with their own name and icon. Each has its own page on this site with the details.

Can NavQL show slow queries in PostgreSQL?

Yes. The Activity tab lists top queries by total time, calls, mean, max and rows from pg_stat_statements. If the extension is not enabled, the screen explains how to turn it on.
