What NavQL does with Dragonfly

Built for the way you work with Dragonfly.

Everything below works on Dragonfly today. Dragonfly speaks the Redis protocol, so it uses NavQL's Redis support, with the differences handled for you.

Its own entry

Dragonfly appears in the connection form with its own name and icon, and the status bar shows the real server.

Keys grouped by prefix

Groups such as session:* open as a grid with key, type, TTL, size and value; edit values of any type.

Memory and hit rate

Used memory and limit, keys, hit rate, evictions and commands per second from INFO.

Clients

CLIENT LIST with Kill. Dragonfly has no CLIENT UNBLOCK, so NavQL does not offer it.

Slow log

SLOWLOG grouped by command, with reset.

Read only

Read-only connections accept only reading commands.

Also included

The details that save time.

  • Settings from CONFIG GET *
  • SSH tunnel and TLS
  • Same app as your SQL databases and MongoDB

Not yet

What NavQL does not do on Dragonfly today.

So you know before you download.

  • Backups (use Dragonfly's own snapshots)

Questions

Good to know.

Does every Redis feature of NavQL work on Dragonfly?

All but Unblock, because Dragonfly does not implement CLIENT UNBLOCK.
