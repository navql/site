What NavQL does with Valkey

Built for the way you work with Valkey.

Everything below works on Valkey today. Valkey speaks the Redis protocol, so it uses NavQL's Redis support, with the differences handled for you.

Its own entry

Valkey appears in the connection form with its own name and icon, and valkey:// URLs are recognized.

Keys grouped by prefix

Groups such as user:* open as a grid with key, type, TTL, size and value; edit values of any type.

Memory and hit rate

Used memory and limit, keys, hit rate, evictions and commands per second, with warnings for failed saves and memory near maxmemory.

Clients

CLIENT LIST with the last command of each client, Unblock and Kill.

Slow log

SLOWLOG grouped by command, with reset.

Read only

Read-only connections accept only reading commands.

Also included

The details that save time.

  • Settings from CONFIG GET *; suggested changes as CONFIG SET
  • SSH tunnel and TLS
  • Same app as your PostgreSQL, MySQL and MongoDB connections

Not yet

What NavQL does not do on Valkey today.

So you know before you download.

  • Backups (Valkey has its own RDB and AOF persistence)

NavQL uses the same features for both and shows Valkey by name, so you always know which server you are on.
