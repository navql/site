What NavQL does with Redis

Built for the way you work with Redis.

Everything below works on Redis today.

Keys grouped by prefix

The sidebar groups keys by their first prefix (user:*, session:*). A group opens as a grid with a row per key: key, type, TTL, size and value.

Edit values of any type

Strings as text; hashes, lists, sets and sorted sets as JSON. Filter the grid by key pattern and by type.

Memory, hit rate, evictions

From INFO: used memory and limit, keys, hit rate, evicted keys and commands per second, with a warning when the last RDB/AOF save failed or memory passes 90% of maxmemory.

Clients

CLIENT LIST with the last command of each client, Unblock for clients stuck on BLPOP or XREAD BLOCK, and Kill.

Slow log

SLOWLOG grouped by command, so the expensive patterns stand out, with a reset button.

Commands, with a safety net

Run Redis commands in the editor. On a read-only connection only reading commands are accepted (GET, HGETALL, SCAN, ZRANGE…).

Also included

The details that save time.

  • Settings from CONFIG GET *, with defaults NavQL knows; suggested changes come as CONFIG SET
  • Quick SCAN 0 MATCH … COUNT 100 for any group from the sidebar
  • SSH tunnel and TLS
  • Works with Valkey and Dragonfly, which appear in the form with their own name and icon
  • Connection colors and tags keep the production cache apart from local

Not yet

What NavQL does not do on Redis today.

So you know before you download.

  • Backups (Redis has its own RDB and AOF persistence)
  • Pub/Sub and stream consumer views

Questions

Good to know.

Is NavQL a free alternative to RedisInsight?

NavQL is free and covers keys, values, memory, clients and the slow log. RedisInsight has more Redis-specific tools, such as module support; NavQL puts Redis in the same app as your SQL databases and MongoDB.

Does NavQL work with Valkey and Dragonfly?

Yes. Both use the Redis protocol. Dragonfly has no CLIENT UNBLOCK, so that button is not offered there.

Does NavQL use KEYS on my server?

Groups are read with SCAN in batches, so browsing does not block the server the way KEYS * can.
